# Institutional GitHub Build Specification

## Mission

Transform Aasish FX's GitHub presence into a credible, evidence-driven engineering portfolio capable of supporting freelance discovery and technical client conversations.

## Identity

Primary positioning:

**AI Systems & Automation Engineer**

Secondary capabilities:

- AI/ML integration
- Python/software engineering
- APIs and integrations
- data engineering
- AWS/serverless
- business automation
- technical research
- evaluation/reliability

## Operating rules

1. Build real artifacts, not decorative placeholders.
2. Prefer deep proof over many shallow repositories.
3. Never fabricate clients, revenue, testimonials, certifications, benchmarks or production status.
4. Separate Research, Prototype, Tested, Measured and Validated status.
5. Every important claim must point toward inspectable evidence.
6. Keep secrets and private information out of public repositories.
7. Use deterministic controls around probabilistic AI components.
8. Add tests and failure cases, not only happy paths.
9. Document assumptions, limitations and reproducibility.
10. Optimize the profile for a reviewer who may spend only a few minutes evaluating the work.
11. Use clear architecture and progressive disclosure to reduce cognitive load.
12. Design each project around a real client problem and a concrete deliverable.
13. Prefer small feasibility experiments before large builds.
14. Keep the portfolio aligned with current market demand for applied AI integration, automation, software, data and cloud work.
15. Before declaring completion, inspect structure, links, code, tests, security, claims and usability.

## Evidence ladder

L0 Claim
L1 Specification
L2 Implementation
L3 Reproducible test
L4 Measurement
L5 Real-world validation

## Required project lifecycle

Problem → Requirements → Architecture → Implementation → Tests → Evidence → Failure analysis → Documentation → Iteration

## Portfolio outcome

A visitor should understand within seconds:

- who Aasish is
- what he builds
- what problems he can solve
- where the strongest evidence is
- how trustworthy the claims are
- how to start a project

## Quality gate

Do not stop at “looks professional.”

The portfolio must increasingly demonstrate **professional execution**.
