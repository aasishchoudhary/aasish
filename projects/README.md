# Aasish FX — Project Portfolio

This page is the roadmap for a portfolio designed around **proof of execution**.

## Project families

| Project | Client problem | Evidence target |
|---|---|---|
| AI Automation Engine | Automate multi-step workflows safely | Tests, policy, telemetry |
| Research Copilot | Turn messy sources into structured research | Reproducible pipeline, citations, evaluation |
| Data Extraction & ETL | Convert semi-structured data into usable datasets | Fixtures, schema checks, quality report |
| API & Workflow Hub | Connect services and automate operations | API contract, integration tests |
| AWS Serverless Platform | Deploy small cloud services reliably | Architecture, deployment docs, logs |
| Business Automation Lab | Automate lead/CRM/ops workflows | Workflow specification, test cases |
| Analytics Dashboard | Turn operational data into decisions | Dataset, SQL, dashboard screenshots |
| AI Content Pipeline | Automate structured content production | Workflow, validation, human review |
| Reliability & Evaluation Lab | Measure AI system behaviour | Datasets, failure taxonomy, regression |

## Execution standard

Every serious project should expose:

**Problem → Architecture → Implementation → Test → Evidence → Limitation → Next step**

Avoid fake client logos, fake testimonials, invented revenue, and unsupported performance claims.

## Status labels

- **Verified** — demonstrated and reproducible in the repository.
- **Prototype** — implemented foundation; broader validation remains.
- **Research** — hypothesis/experimental work.
- **Planned** — architecture defined but implementation not complete.

## Portfolio strategy

The profile should not contain ten shallow “AI” repositories. It should contain a smaller set of deep, clearly differentiated systems that collectively demonstrate software engineering, AI integration, data work, cloud deployment, automation, and professional execution.
